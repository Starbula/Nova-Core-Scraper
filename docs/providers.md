# Artwork providers

NovaCore downloads front box artwork only. ROMs and archives are never uploaded. The providers do not edit ROMs, launch emulators, or write gamelists; the engine controls local image destinations and metadata updates.

## Automatic fallback: Libretro, then LaunchBox

Automatic is the default and requires no account. It tries each source in order until an image has been safely saved. A missing match or a failed image download can fall through to the next source. Authentication/quota failures disable their affected source for that run; healthy sources can continue. Lookup/preparation failures remain failures when no source succeeds, rather than being labelled as proof that no artwork exists. Current Downloads rows identify the successful source.

## Libretro: no account

[Libretro's official documentation](https://docs.libretro.com/guides/roms-playlists-thumbnails/) identifies [thumbnails.libretro.com](https://thumbnails.libretro.com/) as the server used by RetroArch. Its public `Named_Boxarts` directories contain PNG box covers. The [official thumbnail repository](https://github.com/libretro-thumbnails/libretro-thumbnails) explains its naming conventions and catalog organization.

The provider fetches one public HTML directory listing per mapped system and keeps the parsed filename catalog for seven days. It builds exact-name and base-title indexes once per system, so a large library does not scan every remote cover name for each game. Common RetroBat folder names map to the corresponding public platform directories; an unknown system is reported as unmatched without guessing a different platform.

Matching first preserves the complete ROM basename and display title, including region and disc/revision tags. A fallback requires the same normalized base title. Explicit ROM regions must overlap the artwork's region, and explicit edition/disc qualifiers must agree. Without an explicit region, the configured preferred region can select one otherwise unambiguous cover. Duplicate or ambiguous candidates remain unmatched. No edit-distance or partial-title matching is performed; a sequel is never substituted for its predecessor. Unusual ROM names and arcade abbreviations may need a useful existing gamelist title. Coverage and naming are limited by the upstream catalog.

Common GoodTools region labels `(U)`, `(E)`, `(J)` and their combinations are normalized to their regions. Verified-good `[!]` and empty metadata tags are ignored. Meaningful qualifiers such as hacks, discs and revisions are preserved.

## LaunchBox: public catalogue and front covers

LaunchBox's administrator explicitly makes the database [available to other applications](https://forums.launchbox-app.com/topic/30050-tips-and-suggestions-for-games-database/) and explains [using exported image filenames](https://forums.launchbox-app.com/topic/54163-is-there-a-public-way-to-get-images-from-the-launchbox-games-database/). NovaCore downloads the [official Metadata.zip](https://gamesdb.launchbox-app.com/Metadata.zip), not game web pages. Image requests use only filenames actually present in its `GameImage` records with `Type = Box - Front`, on `images.launchbox-app.com`. No account, LaunchBox installation, API key or application credential is required. Upstream artwork retains its owners' rights; this integration is not a public-domain claim or a redistribution license.

The checked 31 October 2026 export is XML: approximately 109 MB compressed and 517 MB for Metadata.xml. NovaCore streams the ZIP to a temporary file and SAX-parses the XML into an indexed SQLite catalogue, retaining only matching fields, aliases and front-cover records. A measured build of that export took 18.61 seconds, used roughly 28.5 MiB peak process memory on the Linux test environment, and produced a 43.3 MB index. This is a measurement, not a Windows performance guarantee. No ROM files are needed for this work.

Preparation runs off the GUI thread and reports download/index progress. ZIP size is capped at 256 MiB, XML at 1 GiB, fields at 4,096 characters and archive member counts are bounded before normal ZIP allocation. Only the known Metadata.xml member is read; no archive paths are extracted into the installation. DTDs/entities, unsafe image filenames and unsupported exports are rejected. The temporary index is closed, committed and synced before atomic replacement. A valid previous index survives interrupted or failed refreshes. Catalogue-only access refusals do not cause another request to the refused catalogue during that session; an already cached index can still resolve images on the separate public image host. Image access refusals remain fatal for that image source.

Catalogue freshness is seven days. Lookups constrain the exact platform, canonical edition qualifiers and exact normalized title or verified alternate name. More than one matching game ID is rejected before inspecting available covers. Images are chosen only for that game, respecting explicit ROM regions (or a verified World cover), then configured preference. Unknown punctuation variants, unsupported regions or distinct editions can remain unmatched. Adjacent systems such as Game Boy and Game Boy Color are never substituted.

## ScreenScraper: account settings and application integration

Normal ScreenScraper settings show only your ScreenScraper username and password. Automatic Libretro/LaunchBox fallback is the working default and needs no account. Before Start, NovaCore checks whether its application integration is configured. If it is missing, the settings screen explains that ScreenScraper is unavailable and offers automatic sources directly. A personal account alone cannot enable an unregistered application.

ScreenScraper has two distinct credentials: the application's developer pair and the user's account. Its [official API documentation](https://www.screenscraper.fr/webapi2.php) directs integrating developers to present their software through its forum and obtain an application ID/password. [RetroBat's user documentation](https://wiki.retrobat.org/navigation/scraping-and-metadata) asks users for their personal ScreenScraper account because the user-facing setup is separate from application integration. NovaCore must provide its own legitimate integration; it cannot use RetroBat's registration. No NovaCore registration or live access verification is implied by this code change.

For maintainers and authorized advanced deployments, `NOVACORE_SS_DEVID` and `NOVACORE_SS_DEVPASSWORD` configure NovaCore's application pair in the process environment. Both must be present and nonblank. `auth.screen_scraper_app_credentials()` reads that pair locally; `auth.screen_scraper_status()` provides a secret-free status message. These helpers make no file/network requests and do not validate registration. A configured pair only enables the normal account flow; the service verifies actual access when scraping starts. Never borrow another application's credentials, share user accounts, or evade service quotas.

Internally, construct `ScreenScraperProvider(cache_dir, devid, devpassword, username, password, region='eu', interval=1.0, workers=1)` from the application pair and the user's account fields. Constructors perform no network requests. The engine calls `prepare(checkpoint)` before launching jobs; `find` also prepares lazily if needed. Preparation negotiates thread and request allowances. Server quota responses update local counters; exhausted quotas and rejected credentials stop the session.

`systemesListe.php` supplies system IDs and frontend aliases. A local `System.screenscraper_id` is an explicit override for systems without a recognized alias. The provider uses `jeuRecherche.php` with a system and title, accepts one exact title match within that system, and selects `box-2D` media by region. Ambiguous results remain unmatched. It does not hash complete disc images or invoke the hash-based `jeuInfos.php` endpoint. This makes matching less expensive locally but cannot identify every renamed ROM.

## Transfer and file guarantees

The coordinator supports 1–16 workers; the Fast preset is 8 workers / 0.25-second request spacing. Request spacing and active transfer slots are shared among a source's workers. Libretro caps active requests at 8 and spacing at a minimum of 0.25 seconds; LaunchBox enforces at least 0.5 seconds. These are NovaCore traffic policies, not published upstream quota promises. ScreenScraper reduces concurrency and request rate to account permissions. A positive `maxdownloadspeed` is documented in Ko/s; streaming shares a conservative budget of 1000 bytes per Ko across all workers, with cancellation-aware waits. Network calls have connection/read timeouts, bounded retries for HTTP 429 and server errors, and cancellation-aware waits that honor `Retry-After`. A cancellation checkpoint is also called while reading and before publishing.

Each source keeps at most 64 MiB of recently validated raw image bytes in memory. Concurrent requests for the same URL coalesce before validation/cache fill; later outputs can reuse the cached bytes. Cache waits are cancellable, invalid images are not cached, and eviction keeps the byte budget bounded. Source URLs are represented by SHA-256 keys, not stored in a persistent artwork cache. Every destination is separately published without replacing existing files. In a controlled transport test, nine output files sharing one cover needed one HTTP request instead of nine; distinct URLs could enter sixteen simultaneous transfers in the shared base provider, while ScreenScraper maxthreads=2 still limited a sixteen-worker configuration to two requests.

Only HTTPS is accepted. Libretro transfers remain on `thumbnails.libretro.com`; LaunchBox uses `gamesdb.launchbox-app.com` and `images.launchbox-app.com`; ScreenScraper transfers remain in the `screenscraper.fr` domain family. Every redirect is checked before following it. Error messages omit remote response bodies, request URLs, and account values. Credential-bearing media URLs are used in memory and must not be logged by callers.

Downloads are limited to 32 MiB and decoded images to 40 million pixels. Pillow verifies and fully decodes media, then writes a normalized RGB/RGBA PNG. HTML error pages, truncated images, and ScreenScraper's text media-status responses are rejected. The provider fsyncs a same-directory temporary file and publishes it without replacing any existing destination: Windows uses no-clobber rename; POSIX uses an atomic hard link. An existing or concurrently created destination raises `FileExistsError` and stays untouched. A filesystem that cannot support safe publication produces an error instead of silently overwriting. Temporary files are removed on failure or cancellation.

RetroBat's [local media documentation](https://wiki.retrobat.org/navigation/scraping-and-metadata) distinguishes box thumbnails (`thumbnail`) from screenshot images (`image`). NovaCore's engine writes into its dedicated image directory and updates these links only when its process gate permits metadata edits.

## Verification scope

Tests use a deterministic replacement for the external HTTP transport with real requests response objects, actual encoded images, threads, and filesystem operations. They exercise conservative matching, catalog persistence/indexing, quotas, retries, cancellation, redirect trust, image limits, PNG conversion, and no-overwrite publication. On 2026-11-01, a Linux smoke check also matched and downloaded a real Libretro cover for NES Super Mario Bros. (World), verified a normalized 325,724-byte PNG, and cleaned the temporary output. ScreenScraper has fixture coverage only; live authentication and Windows runtime behavior remain environment-specific checks.

Additional manual verification on 2026-11-01 indexed the current official LaunchBox export (190,154 games; 206,648 front-cover records), resolved regional Game Boy entries and downloaded the listed Tetris US cover through the production provider. It validated and published a 1,520×1,520 PNG of 3,584,639 bytes. A later Libretro Game Boy endpoint check from the test environment failed at the network layer; this does not establish availability on another computer. Live checks cover selected examples, not the user's whole library. Fixture engine/Tk tests verify fallback, ROM/metadata integrity and live per-console coverage, including cancellation during preflight and deferred metadata writes while RetroBat is detected.

A full production-chain check then used a temporary `Super Mario Land (Europe)` Game Boy entry. Libretro could not serve that environment's request, and automatic fallback downloaded a valid 3,681,729-byte PNG from LaunchBox. The engine's process gate was held active to verify queued metadata, then released to apply the gamelist; the fixture ROM bytes were unchanged and a second run skipped the saved artwork. This simulated the process gate, not an actual RetroBat gaming session.
